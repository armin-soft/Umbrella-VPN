# پژوهش منبع جایگزین فحش فارسی

تاریخ بررسی: ۲۰۲۶-۱۱-۱۶. هدف: **فحش/عبارت رکیک فارسی**، نه مسدودسازی زبان انگلیسی، فینگلیش یا هر محتوای حساس/انتقادی. هیچ منبع بررسی‌شده تضمین تشخیص ۱۰۰٪ ندارد.

## نتیجه

گزینه قابل بررسی برای مرحله بعد **PersianTextGuard** است؛ یک کتابخانه و واژه‌نامه نسخه‌دار، نه API آنلاین با SLA. در این انتشار وابستگی تولیدی جدید یا دانلود خودکار واژه‌ها اضافه نشده و فهرست فعلی ربات جایگزین نشده است. نتیجه یک آزمایش محدود هم نشان داد جایگزینی مستقیم برای مسدودکردن دائمی کاربر امن نیست.

## آزمایش عملی نامزد جدید (خارج از runtime ربات)

بسته npm نسخه **1.5.0** در پوشه موقت، با `--ignore-scripts` نصب شد. فقط دسته‌های `profanity`، `sexual`، `insult` و ورودی‌های با حروف خط عربی/فارسی انتخاب شدند: **۳۱۴ ورودی**. این انتخاب لاتین را حذف می‌کند، اما تشخیص زبان معنایی نیست؛ هنوز بازبینی انسانی فارسی لازم است.

```js
import { ProfanityFilter, WordList } from 'persian-text-guard';
const words = WordList.bundled('profanity', 'sexual', 'insult')
  .filter(w => /^[\p{Script=Arabic}\p{M}\s\u200c\u200d]+$/u.test(w.text));
const filter = new ProfanityFilter(words);
```

نتیجه **۱۶ از ۱۷ نمونه مطابق انتظار** بود؛ این عدد دقت عمومی یا benchmark نیست:

- هفت نمونه رکیک/دورزده، شامل حروف جدا، نقطه‌گذاری، تکرار حرف، پسوند و عبارت ترکیبی تشخیص داده شد.
- «سلام، سفارشم کی می‌رسه؟»، «هر کس سوالی دارد بپرسد»، «کسی خانه نیست»، «تخم مرغ خریدم»، «شیر گاو تازه است» و نام‌های منفرد حیوانات رد نشدند.
- دو نمونه لاتین (یکی انگلیسی و یکی فینگلیش) مطابق شرط «فقط فارسی» تشخیص داده نشدند.
- **مثبت کاذب:** «در زیست‌شناسی درباره سکس صحبت کردیم» تشخیص داده شد، با اینکه جمله آموزشی است، نه فحاشی به مخاطب. دسته sexual با «فحش/رکاکت» یکسان نیست و نیازمند پالایش است.

## پیشنهاد برای جایگزینی بعدی

1. فقط فایل فارسی و دسته‌های مورد توافق، با بازبینی تک‌تک واژه‌های مبهم؛ حذف فینگلیش/انگلیسی و موضوعات غیرمرتبط.
2. نسخه/commit ثابت، checksum، نگهداری مجوزها و بازبینی diff پیش از انتشار. دانلود `master` در هر پیام یا جایگزینی خودکار بدون تأیید ممنوع.
3. تست با corpus واقعیِ بی‌نام و نمونه‌های بی‌ضرر، نام اشخاص، متن آموزشی و دورزدن‌ها؛ ابتدا حالت گزارش بدون مسدودسازی.
4. اگر الزام «بدون فایل محلی» باقی بماند، سرویس خصوصی نسخه‌دار می‌تواند کتابخانه را اجرا کند؛ نیازمند استقرار، timeout، کنترل دسترسی، سیاست حریم خصوصی و fallback است. این معماری در این تغییر پیاده نشده است.
5. هیچ API عمومی فارسی‌محور با تازگی داده، SLA و نرخ خطای قابل اتکا در این بررسی تأیید نشد. ارسال متن کاربران به سرویس ثالث صرفاً برای آزمایش انجام نشد.
